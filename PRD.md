# **Email 2.0 (ActionMail): Презентация и архитектурный манифест платформы**

**Интерактивная корпоративная почта, событийно-ориентированные процессы (EDA) и встраиваемые бизнес-формы**

## **TL;DR — коротко о продукте**

> Если лень читать весь документ — вот суть в 6 пунктах:

1. **Что это.** ActionMail (Email 2.0) — корпоративная почта, в которой само письмо является интерактивной формой: заявку на отпуск, счет на оплату, доступ в Gitlab можно согласовать/отклонить/оплатить в 1 клик прямо внутри письма, не переходя в 1С/SAP/Jira/СЭД.
2. **Как выглядит.** Один почтовый ящик, переключаемый в 4 режима под задачу: **Gmail** (классический список+бланк), **Spike** (мессенджер-переписка с бот-карточками форм), **Kanban** (доска статусов согласования), **Calendar** (сетка отпусков/платежей).
3. **Почему это безопасно.** Внутренние системы (1С, SAP, Jira, СЭД) не выставляются в интернет — общаются с клиентом только асинхронно через шлюз и событийную шину (EDA/Zero Trust). Шлюз не хранит тела писем, только метаданные процесса (Idempotency Key, статус, хэши).
4. **Как подписывают.** Согласование подтверждается либо биометрией (FaceID/WebAuthn) для рутинных вещей, либо настоящей ЭЦП (сертификат .p12, ГОСТ/RSA + PIN) для юридически значимых документов. Каждое действие оставляет неизменяемый аудит-штамп: хэш, время, ключ идемпотентности.
5. **Общие папки.** Помимо личного ящика есть общие корпоративные папки (приказы, счета, helpdesk) с ролевым доступом и механизмом «Взять в работу» — чтобы заявку, которую видит вся группа, не согласовывали дважды.
6. **Текущая фаза.** Сейчас это автономный кликабельный прототип (SPA) без бэкенда — работает полностью в браузере на локальных данных, синхронизируя вкладки через BroadcastChannel, чтобы демонстрировать сценарии стейкхолдерам до старта реальной интеграции с 1С/SAP/Jira.

Дальше — полное описание болей, архитектуры, конкурентов, ролей и дорожной карты.

## **1\. Executive Summary & Видение продукта**

**ActionMail (Email 2.0)** — это корпоративная экосистема коммуникаций и открытая среда исполнения рабочих процессов, трансформирующая электронную почту из пассивного инструмента чтения текста в **полнофункциональное интерактивное рабочее пространство (Actionable Workspace)**.  
В традиционной корпоративной среде письмо является лишь «уведомлением о событии», вынуждающим сотрудника переходить по внешним ссылкам, проходить повторную авторизацию в ERP/СЭД и тратить рабочее время на поиск нужных кнопок. В парадигме Email 2.0 само письмо становится **интерактивным микро-приложением с распределенным состоянием**, позволяя выполнять 90% типовых бизнес-операций в один клик без смены контекста.

### **Ключевой манифест платформы**

*«Don't just read an email — execute the enterprise workflow. Письмо перестает быть статичным слепком текста и становится реактивной точкой взаимодействия с корпоративными системами».*

| Параметр | Традиционный Email (Email 1.0) | ActionMail (Email 2.0)   |
| :---- | :---- | :---- |
| **Суть письма** | Пассивный текст или статичная HTML-верстка | Интерактивная форма с реактивным состоянием |
| **Совершение действия** | Переход по внешней ссылке в 1С, Jira, Documentolog, SAP | 1 клик внутри письма (Согласовать / Отклонить / Оплатить) |
| **Подписание документов** | Открытие сторонних плагинов (NCALayer, КриптоПро) | Встроенный FaceID / WebAuthn или вызов ЭЦП прямо в письме |
| **Синхронизация в группах** | Письмо висит мертвым грузом у всех, риск дублирования | Мгновенное обновление статуса на всех устройствах коллег |

## **2\. Анализ болей корпоративных пользователей**

> * **Синдром расфокуса и усталость от интерфейсов (App Fatigue):** Среднестатистический офисный сотрудник проводит до 2.5 часов в день, переключаясь между почтовым ящиком, таск-трекерами, СЭД и учетными системами ради выполнения 5-секундных действий.  
> * **Проблема неактуального состояния (Stale State):** Когда заявка на согласование счета или счета-фактуры падает руководителю и его двум заместителям, после согласования одним из них у остальных письмо остается в статусе «требует действия», порождая путаницу и повторные клики.  
> * **Фрагментация контекста принятия решений:** Обсуждение задачи происходит в почтовом треде или корпоративном мессенджере, а само действие фиксируется в закрытой внешней СЭД. Вся аналитика и контекст обсуждения теряются.  
> * **Высокий порог подписания:** Необходимость запуска тяжелого ПО для криптографического подписания блокирует мобильность руководителей.

## **3\. Почему Email превосходит 1000 отдельных веб\-фронтендов**

В крупном энтерпрайзе эксплуатируются сотни разнородных мастер-систем (1С:Предприятие, SAP, Oracle, Jira, самописные биллинги). Попытка создать современный веб\- и мобильный интерфейс для каждой из них приводит к колоссальным затратам на разработку, постоянным регрессионным тестам и критическим уязвимостям сетевого периметра.

### **Архитектурная парадигма: Event-Driven Architecture (EDA) & Zero Trust**

\+-----------------------------------------------------------------------------------------+  
| ТРАДИЦИОННЫЙ ПОДХОД: Прямой доступ к веб\-интерфейсам (Хрупко, Дорого, Высокие риски)   |  
|                                                                                         |  
| Сотрудник (Смартфон/ПК) \---\> \[ WAF / VPN \] \---\> 1С:Предприятие / Jira / SAP / СЭД       |  
| Уязвимости: публичный периметр, риск SQL-инъекций, падение СУБД от пиковых сессий        |  
\+-----------------------------------------------------------------------------------------+  
                                           VS  
\+-----------------------------------------------------------------------------------------+  
| ПАРАДИГМА EMAIL 2.0: Асинхронный событийный контур (Безопасно, Масштабируемо, Надежно)  |  
|                                                                                         |  
| Сотрудник (ActionMail) \<---\> \[ ActionMail Gateway \] \<--- Event Bus \---\> Внутренние      |  
| (TLS / WebSockets / Push)    (DMZ / Внешний шлюз)    (MQTT / Webhooks)  системы (1С/SAP)|  
|                                                                         \[Изолированы\]   |  
\+-----------------------------------------------------------------------------------------+

### **Преимущества архитектуры:**

> 1. **Письмо как неизменяемый инстанс события (Immutable Message Instance):** Каждое сообщение содержит в себе точный контекст события на момент отправки (Payload \+ JSON Schema \+ Workflow ID).  
> 2. **Изоляция ядра и безопасность периметра (Zero Trust):** Внутренние корпоративные базы данных и учетные системы не выставляются в публичный интернет. Они взаимодействуют со шлюзом исключительно асинхронно через события, что исключает риск прямых атак и SQL-инъекций.  
> 3. **Снятие High-Availability и High-Load (HA/HL) нагрузки:** При массовой рассылке (например, утверждение годовых бонусов на 50 000 сотрудников) ERP-система не сталкивается со шквалом одновременных тяжелых сессий. Нагрузку по рендерингу несет клиентское приложение, а подтверждения поступают в буферизированные очереди.

## **4\. UX: Единый почтовый ящик в 4-х режимах отображения**

Пользователю не требуется переучиваться: в основе сервиса лежит привычная ментальная модель почтового ящика, которую можно переключить в любой из четырех специализированных видов под текущую задачу.

| Режим | Интерфейсная парадигма | Целевой сценарий использования   |
| :---- | :---- | :---- |
| **Gmail View** | Классический 3-панельный интерфейс (Папки — Список писем с бейджами — Интерактивный бланк заявки). | Полноэкранная офисная работа на десктопе, детальный аудит длинных таблиц параметров и вложенных файлов. |
| **Spike Messenger View** | Conversational UI. Переписка очищена от служебных заголовков и цитат. Формы рендерятся как компактные бот-карточки. | Мобильные клиенты, быстрые согласования «на бегу», мгновенный обмен короткими комментариями. |
| **Kanban View** | Доска процессов со столбцами: «Входящие заявки» → «На проверке» → «Согласовано» → «Отклонено». | Triage входящего потока задач для руководителей, визуальный контроль очередей согласования счетов и отпусков. |
| **Calendar View** | Сетка месяца и недели с цветными полосами событий, извлеченных из полей дат в письмах. | Контроль пересечений отпусков в команде, график командировок, дедлайны по кассовым разрывам и оплатам счетов. |

## **5\. Архитектура интеграций, SSO и Sandboxed Mini-Apps**

Платформа спроектирована по принципу модульного шлюза, разделяющего клиентский уровень и внутреннюю корпоративную инфраструктуру.

\+------------------------------------------------------------------------------------------+  
|                             ACTIONMAIL CLIENT APPLICATION                                |  
|   \[ Forms Engine \]            \[ WeChat-style Sandboxed Mini-Apps \]      \[ E-Sign Mod \]   |  
\+------------------------------------------------------------------------------------------+  
                                              │ HTTPS / WSS / Push Notifications  
                                              ▼  
\+------------------------------------------------------------------------------------------+  
|                            ACTIONMAIL SECURE GATEWAY (DMZ)                               |  
|   \- SSO & Identity Provider (Keycloak, Microsoft Entra ID, SAML 2.0, OpenID Connect)     |  
|   \- Realtime State Bus & Group Sync Engine (Valkey / MQTT WebSockets Broker)              |  
|   \- Idempotency & Security Validator                                                     |  
\+------------------------------------------------------------------------------------------+  
                                              │  
                     ┌────────────────────────┼────────────────────────┐  
                     │ Event Bus (MQTT/HTTP)  │ REST / Webhooks / gRPC │  
                     ▼                        ▼                        ▼  
            ┌──────────────────┐    ┌───────────────────┐    ┌────────────────────┐  
            │ 1С:Предприятие / │    │ Jira / Service    │    │ Documentolog /     │  
            │ SAP Master ERP   │    │ Desk Core         │    │ Custom СЭД         │  
            └──────────────────┘    └───────────────────┘    └────────────────────┘

### **Концепция Sandboxed Mini-Apps (WeChat / Telegram Pattern)**

Если бизнес-процесс превышает возможности декларативной плоской формы (например, бронирование места на интерактивной 2D-карте офиса или выбор оборудования из каталога 1С с 50 зависимыми параметрами), письмо содержит защищенный **Sandboxed Webview Mini-App**. Мини-приложение исполняется в изолированном контексте, автоматически наследуя авторизационный токен пользователя и ID процесса.

## **7\. Public Folders 2.0: Общие корпоративные папки**

Мы возрождаем популярную концепцию общих папок Exchange/Outlook, адаптируя ее под современные веб\-стандарты и микросервисы.

> * **Дерево общих папок в навигации:** Ниже персонального ящика отображаются структурированные папки компании: 01\_Приказы\_и\_регламенты, 02\_Бухгалтерия\_Счета, 03\_IT\_Helpdesk.  
> * **Ролевой доступ (RBAC & ACL):** Тонкая настройка прав (только чтение приказов, создание заявок, администрирование).  
> * **Механизм взятия в работу (Claim System):** Заявка, поступившая в общую папку, видна всей рабочей группе. Как только один специалист нажимает «Взять в работу», у остальных отображается аватар ответственного, исключая дублирование.

## **8\. Встроенные Action-расширения: ЭЦП, FaceID и B2B-Платежи**

> 1. **Юридически значимая подпись (ЭЦП / GOST / RSA):** Интеграция с локальными и облачными криптопровайдерами (NCALayer, eGov QR, WebAuthn). Подписание служебной записки, приказа или договора формирует неизменяемый штамп времени и криптографический хэш.  
> 2. **FaceID / Биометрическое подтверждение:** Для рутинных внутренних согласований (запрос отпуска, выдача доступов) используется мгновенная биометрическая верификация через WebAuthn / Passkeys без ввода паролей.  
> 3. **B2B-Платежи в 1 клик:** Счета на оплату содержат кнопку прямого проведения платежа через банковские B2B-шлюзы (Kaspi B2B, корпоративные карты) с автоматическим формированием платежного поручения и закрытием проводки в 1С.

## **9\. Встроенный оркестратор многошаговых процессов (Workflow Engine)**

Платформа позволяет настраивать цепочки согласований любой сложности без внедрения тяжелых монолитных BPMN-движков:

\[ Шаг 1: Инициатор \]       \[ Шаг 2: Тимлид \]        \[ Шаг 3: Бухгалтерия \]      \[ Завершение \]  
Заполняет форму       ───► Согласовывает с    ───► Проверяет лимиты     ───► 1С проводит  
«Заявка на обучение»       FaceID (в письме)        и подписывает с ЭЦП         приказ авто

> * **Динамический роутинг:** После завершения шага письмо автоматически меняет адресата и статус, обновляя таймлайн прогресса в треде.  
> * **Контроль SLA и дедлайнов:** Автоматическая отправка напоминаний и эскалация руководителю при задержке согласования.  
> * **Неизменяемый аудит-лог (Audit Trail):** Полная история резолюций с хэшами подписей сохраняется в служебных заголовках письма.

## **10\. Информационная безопасность и защита коммерческой тайны**

Для прохождения строгого аудита корпоративной службы информационной безопасности (CISO) в платформе реализованы следующие принципы:

> * **Принцип минимального хранения данных:** Шлюз ActionMail Gateway не сохраняет тело коммерческих писем и вложенных файлов. Он оперирует исключительно метаданными процессов (State ID, Status, Hashes).  
> * **Защита от повторного исполнения (Idempotency Key):** Каждое действие маркируется уникальным криптографическим ключом, что исключает повторное проведение операции при сбоях сети.  
> * **End-to-End шифрование служебного payload:** JSON-схема и поля формы передаются в зашифрованном контейнере с валидацией корпоративных сертификатов.

## **11\. 100% Обратная совместимость (Progressive Enhancement)**

Сервис базируется на стандартном транспорте (SMTP / IMAP / JMAP) и использует MIME-multipart структуру контейнера:

> * text/plain — текстовая сводка для терминальных клиентов.  
> * text/html — сверстанный адаптивный HTML с кнопкой-ссылкой *«Открыть и подписать заявку в браузере»* (Magic Link с JWT) для сторонних почтовиков (Apple Mail, Thunderbird, Roundcube).  
> * application/vnd.richform+json — декларативная схема формы, статусы и роутинг для нативных клиентов ActionMail.

## **12\. Бизнес-метрики и Дорожная карта (Roadmap)**

### **Ожидаемый бизнес-эффект от внедрения:**

> * **Сокращение Time-to-Approve:** Среднее время согласования документов снижается с **18 часов до 8 минут**.  
> * **Экономия до 70% IT-бюджета:** Отсутствие необходимости проектировать и поддерживать десятки кастомных мобильных веб\-фронтендов для каждой внутренней системы.  
> * **Снижение нагрузки на Helpdesk и HR на 65%:** Исключение дублирующих вопросов о текущем статусе документов.
